# 决定 0001：Windows 地板与 Qt 版本矩阵

**状态**：**已决定（2026-10-25）——选 B：Windows 产物整个用 Qt 6.7，支持基线是 Windows 10 1607**
**相关**：[`docs/evidence/windows-import-tables.md`](../evidence/windows-import-tables.md)、
[`docs/DEVELOPMENT_PLAN.md`](../DEVELOPMENT_PLAN.md) §4 R10、README 的「Why Windows 10 1607」

## 决定

**Windows 2016（10 1607，build 14393）一定要能用。** 因此：

- **Windows 的构建与发布用 Qt 6.7** ✔ —— 它是地板还在 1607 的最新版本 ✔
- **承诺的支持基线从 1809 降到 1607** ✔，README 与发布说明都改 ✔
- **导入表门禁的两个阈值都变成 1607** ✔：自有二进制 `--floor 1607 --strict` ✔，
  整个发布包 `--package-floor 1607` ✔ —— 数字就是承诺的那个 ✔
- **macOS 与 Linux 继续用 Qt 6.8.3** ✔ —— 它们的地板与 Windows 无关 ✔
- **不选 C**（不出两个 Windows 包）✔ —— 一个包，一套门禁，一条发布腿 ✔

代价说在前面：**Windows 用户拿到的 Qt 是 6.7，不是 6.8** ✔，拿不到 6.8 的缺陷修复与
安全修复 ✔。这是"Windows 2016 要能用"这个前提的直接结果 ✔。

## 为什么不是别的

### 不是 A（保持 1809）

测量说 6.7 的地板是 1607 ✔ —— 所以"没有哪个 Qt 能跑在 1607 上"这个理由不成立 ✔。
需求是硬要求 ✔，A 不满足它 ✔。

### 不是 C（出两个 Windows 包）

C 的代价是：Windows 发布作业多一条腿 ✔、CI 的 Windows 腿要同时跑两个 Qt 版本 ✔、
导入表门禁要按产物分两个阈值 ✔、文档要说清哪个包是哪个 ✔、老 Qt 那条分支要一直维护 ✔。

**这些代价换来的只是"主力用户能用新 Qt"** —— 而 B 用"主力用户也用 6.7"换掉了它 ✔。
既然 2016 的用户是硬需求 ✔，就选代价更小、也更少东西会漂移的那条 ✔。

## 支撑这个决定的事实

| 事实 | 数值 | 怎么来的 |
| --- | --- | --- |
| 我们自己的 `openscrt.exe` 的地板 | **1607** | ConPTY 的三个入口点改成运行期解析 ✔；门禁 `--floor 1607 --strict` 卡着 ✔ |
| Qt 6.5 / 6.6 / 6.7 的地板 | **1607** | run **#40205287033**（`qt-floor-report` ✔），按 kernel32 导出表测的 ✔ |
| Qt 6.8 的地板 | **1709** | 同一个 run ✔；`Qt6Core.dll` 导入 `SetThreadDescription` ✔，真机 1607 不导出它 ✔ |
| 代码是否用了 6.8 专有 API | **没有** ✔ | `QKeyCombination`、`QStringDecoder` 等都搜不到 ✔ |
| 构建是否写死了 Qt 最低版本 | **没有** ✔ | `find_package(Qt6 REQUIRED COMPONENTS Core)` ✔ |
| CI 是否能对着 6.7 跑 | **能** ✔ | run **#40206146819**：Windows 上用 Qt 6.7.3 完整构建并跑完单测（33 个测试二进制 100% 通过 ✔），同一轮量出 **Qt 6.7 包的导入地板 = build 14393 = 1607** ✔。现在 **CI 的 Windows 腿每个 push 都是 6.7** ✔（run **#40206652403**：门禁报出 `package floor: Windows 10.0 build 14393`，整个包 —— exe、四个 Qt 库、vcpkg 的动态库 —— 全在 1607 ✔） |

## 剩下的

- **1607 的真机验收还没有** ✔（P1-A7 ✔）。承诺一个没在真机上跑过的地板，哪怕测量说它行，
  也只是"导入表说它行" ✔ —— 值得找一台 2016 的机器把整个流程走一遍 ✔。
- **Qt 6.7 的安全更新** ✔：以后 6.7 有 CVE 时，Windows 用户的那个包要手工往回带 ✔
  （这是 B 的长期代价 ✔）。`qt-floor-report` 每周会重新量一遍各个 Qt 系列的地板 ✔，
  哪天 6.7 的地板被抬高了，那条腿会红 ✔ —— 不会悄悄破掉承诺 ✔。
- **CI 的 Windows 腿现在只测 6.7** ✔，不再测 6.8 on Windows ✔（macOS/Linux 腿仍然测 6.8 ✔）。
